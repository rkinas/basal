- **The `-FP8` checkpoints are refused by the modes that cannot read them** (`--mode eager`, `mps`, `mlx`, `strix`,
  `tpu`). basal 2.8.0 loaded an NVIDIA ModelOpt FP8 checkpoint in `--mode eager` and `--mode mps` without its scales
  and served wrong answers with no error; the log showed only a warning from transformers ("Unknown quantization
  type, got modelopt"). On basal-omni-1.0-mini-FP8 in `--mode eager`, 24 of 68 answers on a test set kept the top
  answer of the bf16 model.
  - **Which checkpoints:** every public `-FP8` repository: basal-omni-1.0-mini-FP8, -ultra-FP8 and -max-FP8,
    basal-2.0-mini-FP8, -4.5B-FP8 and -max-FP8, and the basal-1.5 and basal-1.0 `-FP8` checkpoints.
  - **Who got it without asking:** without `--mode`, basal-omni's `-FP8` checkpoints ran in `eager` on every NVIDIA
    GPU except Hopper (H100, H200) with the `flash_attn_3` package and Blackwell workstation GPUs (RTX PRO 6000,
    RTX 50xx): for example A100, A10, L4, L40S, RTX 6000 Ada, RTX 30xx and 40xx, and B200. On a machine without a GPU
    every `-FP8` checkpoint ran in `eager`, and on Apple Silicon without mlx in `mps`.
  - **Now:** such a start stops at once, before any weights download, with a message naming `--mode fast` (it reads
    the FP8 layers on a CUDA GPU) or `--mode vllm`, or the bf16 model. Without `--mode`, a machine whose default
    would be one of those modes stops the same way. The `-NVFP4` checkpoints, which failed to load outside
    `--mode vllm`, get the same message.
  - `--mode fast`, `fp8` and `vllm` serve the `-FP8` checkpoints as before, and every other start answers as in 2.8.0.
