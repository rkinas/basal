- **A bounded server under load** (`basal-serve`): requests in flight were unbounded, a request could wait for ever
  behind a stalled engine, a request whose prompts held gigabytes of text (a long state times thousands of labels and
  two option orders) was rendered and tokenized whole, and that work held the event loop, so `/health` and every other
  client waited. Now `--max-requests N` (1,024 by default) answers a request beyond N in flight with 503
  (`OVERLOADED`, `Retry-After: 1`; the Python client's `NotReady`, retried) before any work; `--request-timeout S`
  (off by default) answers 504 (`TIMEOUT`) and drops the request's queued work; `--max-prompt-mb` (512 by default)
  refuses with 422, before anything is rendered, a request whose prompts would hold more text; and the prompts of a
  request holding over 1 MiB of text are rendered and tokenized in a thread of their own, while the event loop
  answers. A server decided in process under several event loops (a test, a tool calling `asyncio.run` more than
  once) no longer waits for ever when a request's preparation yields before its queue entry. Answers are unchanged.
