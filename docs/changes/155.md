- **`basal_state_cache_prefix_hits_total` counts the prefixes reused, not the matches found** (`--state-cache-gb`,
  `--prefix-cache on`): the counter rose for every match the cache found, including the matches the engine then
  discarded and recomputed, so it reported reuse that had not happened. It now rises only where a caller continues
  the entry. **The number falls after upgrading** — on a Qwen3.5 (Gated DeltaNet) server it may fall to near zero,
  because a recurrent state exists only after an entry's last token, so a match that ends inside one cannot be
  continued. That is the counter becoming correct, not the cache regressing: which states are reused and which are
  recomputed does not change, and no answer, probability or timing moves. Dashboards and alerts keyed on a cache-hit
  ratio need rebaselining. `StateCache.longest`'s `use` hook takes `(key, matched length, state length)` instead of
  the key alone; an out-of-tree `use=lambda key: ...` raises `TypeError` on its first cache match. Contributed by
  Maciek Bajor (@bajor), [#155](https://github.com/rkinas/basal/pull/155).
