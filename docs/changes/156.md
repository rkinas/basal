- **A Qwen3.5 state that differs inside a cached one continues a shorter cached state instead of running again**
  (`--state-cache-gb`, `--prefix-cache on`): the lookup returned its longest match, and a recurrent state exists only
  after its entry's last token, so a match ending inside one was rejected and the whole state ran again, even where a
  shorter cached state ended exactly where this one still agreed. That entry is now rejected during the search, which
  carries on to the longest cached state the request begins with whole and continues that, and that state is kept
  rather than replaced, so every later state diverging at the same token continues it too. It is the common case on
  this backend rather than an edge: every state edited inside a cached one lands there. The answers do not change.
  `basal_state_cache_prefix_hits_total` rises where reuse now happens: on a Qwen3.5 server this undoes the near-zero
  reading that the prefix-hit counting change in this release warns of, because the matches called uncontinuable
  there are continued here. Rebaseline a cache-hit alert against both. Contributed by Maciek Bajor (@bajor),
  [#156](https://github.com/rkinas/basal/pull/156).
- **A root a longer cached state holds whole is reused instead of recomputed** (`--state-cache-gb`,
  `--prefix-cache on`, `--mode fast` / `mlx`): the incremental path continues a cached state, and a root that state
  already holds has nothing to continue, so it was computed again from the keys and values the cache was holding.
  They are now copied from that entry, so such a request pays a copy of its state instead of pass 1: an agent that
  rewound a step, a client resending the first half of a document, a retry of a truncated trace. The copy is stored
  under its own key, so the cache holds those rows twice and evicts within its budget sooner until one of the two
  entries goes. Gemma 4 does not copy, a sliding layer holding fewer tokens than a root of that length keeps; it now
  passes such an entry over during the search and continues the longest shorter state it can, where it ran the whole
  root again before. `basal_state_cache_prefix_hits_total` rises accordingly, and `docs/SERVING.md` says which
  matches it still does not count. Contributed by Maciek Bajor (@bajor),
  [#156](https://github.com/rkinas/basal/pull/156).
